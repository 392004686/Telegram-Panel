# 客户管理

## 页面结构

- **客户列表**：沿用账号列表的筛选、复选、固定操作列和分页结构，支持按客户分类、查询状态、导入批次及关键字筛选。
- **客户分类**：沿用账号分类管理方式，支持分类新增、编辑、删除和客户数量统计；删除分类后客户档案保留并显示为未分类。
- **查找用户**：入口位于客户列表，不再挂在账号“加入的群组”弹窗。可选择一个启用且 Telegram 状态可用的执行账号，按手机号或 `@username` 查询；查询结果写回客户档案。

客户列表支持批量修改分类和批量删除。单行操作支持重新查询、查看详情和删除；详情展示 Telegram ID、昵称、用户名、手机号、查询时间、分类与导入批次。

## API 补充

- `GET /api/panel/customers/{id}`：读取客户详情。
- `POST /api/panel/customers/lookup`：按输入新建或复用客户并立即查询。
- `POST /api/panel/customers/{id}/lookup`：使用指定执行账号重新查询已有客户。
- `POST /api/panel/customers/batch`：批量设置分类或删除。
- `PUT/DELETE /api/panel/customer-groups/{id}`：编辑或删除客户分类。

手机号查询可能因对方隐私设置返回未确认；执行账号异常时记录为查询异常。回滚到 `aeb683c` 不会删除客户数据，但旧界面不会显示本节新增入口。

适用版本：Telegram X 定制版 2026-09-15 及以后。

## 当前能力

- 从“客户管理”批量粘贴导入国际格式手机号或 `@username`。
- 每次导入生成独立批次；重复客户不重复建档，但继续关联新批次和客户分组。
- 客户列表支持关键字、查询状态和客户分组筛选。
- 客户与分组是多对多关系，为后续按状态、批次、分组创建交互任务预留数据结构。

当前版本尚未把客户批量查询接入任务中心。可在“账号列表 → 查看加入的群组 → 手动查找用户是否存在”使用指定登录账号做单条验证；测试结果不会写入客户库。

手机号查找通过 Telegram 联系人导入接口完成。返回“未找到”既可能表示号码未注册，也可能表示对方限制通过手机号发现；用户名查询结果更适合直接判断公开账号是否存在。

## 数据与升级

客户、分组、批次及关联关系写入主 SQLite 数据库。升级时迁移 `20260915090000_AddCustomerManagement` 自动建表；现有账号、群组和任务数据不变。

成功判据：页面可导入客户，刷新后数据仍存在，重复导入只增加批次关联；单条查找能显示 User ID、用户名及限制状态。

失败排查：先检查数据库迁移日志，再确认执行账号正常登录且未处于失效、冻结或限制状态。

回滚：切回旧镜像后新表会保留但被旧版本忽略；如需彻底回退，先备份数据库，再执行该迁移的 `Down`。

## 账号筛选

客户管理下的“账号筛选”支持手机号与 `@username`。手机号可以写成 `+1 123456789`、`+1123456789` 或纯数字，空格会在查询前移除。批量查询可选择指定账号或账号分类轮询，并设置随机/队列顺序和最小、最大查询间隔。查询结果只有在客户已存在时更新客户档案；未收录目标仅显示在当前结果表。
